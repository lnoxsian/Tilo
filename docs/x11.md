# X11 Integration

This document covers tilo's X11 connection, event model, mouse grabs, XRandR integration, and diagnostics.

---

## Connection

Tilo uses `x11rb`'s `RustConnection` throughout. On startup, `X11Context::new()`:

1. Connects to the display identified by `$DISPLAY`.
2. Selects the screen (default screen 0).
3. Caches the root window ID, screen width, and screen height.

If `$DISPLAY` is unset or unreachable, tilo exits with an error.

---

## Becoming the Window Manager

`X11Context::become_wm()` selects the following event mask on the root window:

| Event Mask | Purpose |
|---|---|
| `SUBSTRUCTURE_REDIRECT` | Intercept `MapRequest` and `ConfigureRequest` from all clients |
| `SUBSTRUCTURE_NOTIFY` | Receive `MapNotify`, `UnmapNotify`, `DestroyNotify`, `ConfigureNotify` |
| `STRUCTURE_NOTIFY` | Receive `ConfigureNotify` for the root itself |
| `PROPERTY_CHANGE` | Receive `PropertyNotify` for root-level EWMH property updates |
| `KEY_PRESS` | Receive grabbed key events |
| `BUTTON_PRESS` | Receive grabbed button (mouse) events |
| `POINTER_MOTION` | Receive motion events during mouse drags |

Only one X11 client can hold `SUBSTRUCTURE_REDIRECT` on the root at a time. If another WM is already running, the request returns an `Access` error, which tilo maps to `X11Error::AnotherWmRunning` and exits cleanly.

---

## Managed Client Events

For each managed (non-`override_redirect`) client, tilo selects:

| Event Mask | Purpose |
|---|---|
| `PROPERTY_CHANGE` | Track title, urgency, and hints changes |
| `STRUCTURE_NOTIFY` | Track unmapping and destruction |
| `ENTER_WINDOW` | Pointer-based focus (click-to-focus behavior) |

`override_redirect` windows — menus, tooltips, and other bypass UI — are not managed and receive no event selection.

---

## Event Dispatch Flow

```
X server → wait_for_event()
  │
  ├── MapRequest       → client lifecycle: adopt or skip
  ├── ConfigureRequest → honor size hints or hold geometry
  ├── UnmapNotify      → withdrawal or workspace-switch unmap
  ├── DestroyNotify    → remove client from registry and layout
  ├── PropertyNotify   → title / urgency / hints update → bar refresh
  ├── KeyPress         → InputManager → Action → WM operation
  ├── ButtonPress      → mouse grab handler → focus / drag
  ├── MotionNotify     → floating move / resize drag update
  ├── ButtonRelease    → end drag
  ├── ClientMessage    → EWMH protocol handling
  ├── RandrNotify      → MonitorManager reconciliation → retile
  └── ExposeEvent      → redraw bar or launcher overlay
```

Requests are queued by `x11rb` and flushed after each batch of state-changing operations. A lost connection is distinguished from client-specific protocol errors and returns `WmError::ConnectionLost` from the event loop.

## XRandR

### Startup Query

At startup, tilo queries XRandR for:
- Active connected outputs
- CRTC geometries (position, size)
- Primary output flag

Cloned outputs sharing a CRTC position/size are collapsed into one logical monitor. If XRandR is missing or returns no active CRTC, the root screen is treated as a single monitor.

### Hotplug

`RandrNotify` events trigger reconciliation:

1. Re-query outputs and CRTCs.
2. Match existing monitors by XRandR ID or position → **preserve workspace assignments**.
3. Assign unused workspace IDs to new monitors.
4. Release disconnected monitors' workspaces so clients remain reachable.

### Multi-Monitor Layout

```
Monitor 0 (primary)        Monitor 1
┌─────────────────┐        ┌──────────────┐
│  Workspace 1    │        │  Workspace 4  │
│  [bar]          │        │  [bar]        │
│  tiled clients  │        │  tiled clients│
└─────────────────┘        └──────────────┘
```

Each monitor independently tracks its active workspace.

## Cursors and Mouse Grabs

### Cursors

| Context | Cursor Shape |
|---|---|
| Root window (idle) | Normal arrow |
| Floating window move (drag active) | Fleur (move) cursor |
| Floating window resize (drag active) | Sizing/resize cursor |

Cursors are loaded from the X11 cursor font.

### Button Grabs

| Binding | Behavior |
|---|---|
| `Mod + Button1` (press on client) | Begin floating window move drag |
| `Mod + Button3` (press on client) | Begin floating window resize drag |
| `Button1` on unfocused client | Click-to-focus (unmodified) |

Lock and Num Lock modifier variants are included in all grabs to avoid interference.

The **focused** client releases the unmodified `Button1` grab so applications retain normal click behavior.

---

## Key Grabs

Keys are grabbed on the root window. Grabs are installed after parsing keybindings and reinstalled on hot-reload. Lock and Num Lock modifiers are included in all grabs.

Key parsing uses X11 keysym names (`Return`, `space`, `h`, `F1`, `Tab`, `grave`, etc.). The `xev` tool is useful for identifying keysym names.

---

## Signal Handling

The event loop checks signal flags before each event batch:

| Signal | Effect |
|---|---|
| `SIGUSR1` | Toggle launcher overlay |
| `SIGHUP` | Reload configuration from disk |
| `SIGINT` | Graceful shutdown |
| `SIGTERM` | Graceful shutdown |
| `SIGCHLD` | Ignored — prevents zombie children from autostart / spawn |

### Graceful Shutdown

On `SIGTERM` or `SIGINT`:

1. All managed windows are unmanaged (borders restored, `WM_STATE` cleared).
2. WM-owned windows (bar, launcher, supporting window) are destroyed.
3. X11 connection is closed.
4. Process exits with code `0`.

## Environment Requirements

| Requirement | Notes |
|---|---|
| `$DISPLAY` set and reachable | Required; tilo exits cleanly if unset |
| No other WM running | Required; tilo detects and reports cleanly |
| XRandR extension | Recommended; falls back to root screen if unavailable |
| Fonts available | Required for bar/launcher; falls back to X11 core fonts |
| Linux OS | `/proc` modules are Linux-specific; bar still works without them |

> [!IMPORTANT]
> Starting tilo inside an existing desktop session (GNOME, KDE, i3, etc.) will fail because the session already has a WM holding `SUBSTRUCTURE_REDIRECT`. Always use Xephyr for development.

## Diagnostics

### Startup Log

```
[INFO  tilo::x11] Connected to X11 server.
[INFO  tilo::x11] Managing root window: 0x5a1
[INFO  tilo::x11] Screen dimensions: 1280x720
[INFO  tilo::wm] Successfully became the window manager.
[INFO  tilo::wm] Entering X11 event loop...
```

### Common Failures

| Error | Cause | Fix |
|---|---|---|
| `Failed to connect to X server` | `$DISPLAY` unset or unreachable | Set `$DISPLAY` or start Xephyr |
| `Another window manager is already running` | WM already owns the display | Use Xephyr or stop the existing WM |
| `Failed to enable statusbar` | Font unavailable or geometry error | Check fonts; non-fatal warning |
| `Failed to manage pre-existing windows` | Protocol error on adoption | Non-fatal; remaining windows still managed |

### Inspection Tools

```bash
xprop -root                       # View all root window properties
xprop -root _NET_CLIENT_LIST      # List managed windows
xwininfo -root -tree              # Tree of all windows and geometries
xrandr --query                    # List XRandR outputs and modes
xev                               # Log X11 events (find keysym names)
xdpyinfo                          # Display server capabilities
```
